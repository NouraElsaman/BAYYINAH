# BAYYINAH — Deployment Guide

This guide covers local development, production deployment to Render, and Qdrant Cloud setup.

---

## Prerequisites

| Requirement | Details |
|-------------|---------|
| Docker + Docker Compose | For local development |
| Python 3.11 | For direct backend runs |
| Node.js 18+ | For frontend dev |
| Groq account | API key at [console.groq.com](https://console.groq.com) |
| Qdrant Cloud account | Free tier at [cloud.qdrant.io](https://cloud.qdrant.io) |

## Local Development

### 1. Environment setup

```bash
cp .env.example .env
```

Edit `.env` with your real values:

```env
GROQ_API_KEY=gsk_...your_key_here...
QDRANT_URL=https://YOUR-CLUSTER.eu-west-2-0.aws.cloud.qdrant.io
QDRANT_API_KEY=eyJhbGci...your_jwt...
QDRANT_COLLECTION=egypt_legal_rag
GROQ_MODEL=openai/gpt-oss-120b
```

### 2. Start with Docker Compose

```bash
docker compose up --build
```

This starts:
- Backend on port 8000
- Frontend on port 3000
- Qdrant on port 6333 (if using local Qdrant instead of cloud)
- Redis on port 6379

### 3. Start without Docker (development)

**Backend:**
```bash
cd backend
python -m venv .venv
.venv\Scripts\activate      # Windows
source .venv/bin/activate   # Linux/macOS
pip install -r requirements.txt

uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

**Frontend:**
```bash
cd frontend
npm install --legacy-peer-deps
npm run dev
```

Open http://localhost:3000.

## Production Deployment — Render Blueprint

### Architecture on Render

```
Render services:
  digitlaw-backend  (Docker, standard plan, Frankfurt)
  digitlaw-frontend (Docker, starter plan)
  digitlaw-redis    (managed Redis, starter plan)

External services:
  Qdrant Cloud      (EU-West region, free/starter cluster)
  Groq API          (openai/gpt-oss-120b)
```

### Step 1 — Push to GitHub

The repository must be public or connected to Render.

```bash
git init
git add .
git commit -m "feat: initial release — BAYYINAH v1.0"
git remote add origin https://github.com/YOUR-USERNAME/YOUR-REPO.git
git push -u origin main
```

### Step 2 — Create Render Blueprint

1. Log in to [render.com](https://render.com)
2. **New** → **Blueprint**
3. Connect your GitHub repository
4. Render reads `render.yaml` and creates 3 services
5. Click **Apply**

### Step 3 — Configure Secrets in Render Dashboard

For the `digitlaw-backend` service, add these as **Environment Variables** in the Render dashboard (not in render.yaml — never put secrets in yaml):

| Variable | Value |
|----------|-------|
| `GROQ_API_KEY` | Your Groq API key |
| `QDRANT_URL` | Your Qdrant Cloud cluster URL |
| `QDRANT_API_KEY` | Your Qdrant JWT API key |

The following are already set in `render.yaml`:
- `GROQ_MODEL=openai/gpt-oss-120b`
- `QDRANT_COLLECTION=egypt_legal_rag`
- `ENVIRONMENT=production`
- `SECRET_KEY` (auto-generated by Render)
- `REDIS_URL` (auto-wired from `digitlaw-redis`)

### Step 4 — Update CORS for Production

After deployment, update the CORS_ORIGINS in Render dashboard for `digitlaw-backend`:

```
CORS_ORIGINS=["https://digitlaw-frontend.onrender.com"]
```

Replace with your actual frontend URL.

### Step 5 — Update Frontend API URL

For `digitlaw-frontend`, Render already sets:
```
NEXT_PUBLIC_API_URL=https://digitlaw-backend.onrender.com
```

## Render Plan Considerations

### Current Configuration (render.yaml)

| Service | Plan | RAM | Cost |
|---------|------|-----|------|
| `digitlaw-backend` | standard | 512 MB | ~$7/month |
| `digitlaw-frontend` | starter | 256 MB | Free |
| `digitlaw-redis` | starter | 256 MB | Free |

### RAM Warning

The backend loads two large models at startup:
- `BAAI/bge-m3` embedding model: ~500 MB on disk, ~900 MB RAM
- `BAAI/bge-reranker-v2-m3`: ~1.1 GB on disk, ~1.2 GB RAM

**Total model footprint: ~2.1 GB RAM**

The standard plan (512 MB) will OOM on first model load.

**Recommended solutions:**
1. **Upgrade to pro plan (2 GB RAM):** Render pro is $25/month — necessary for this model combination
2. **Download models at deploy time:** Pre-pull models into the Docker image during build (`huggingface-cli download` in Dockerfile) and mount a persistent disk — avoids re-downloading on restart
3. **Use smaller models (with quality tradeoff):** Not recommended — see PROJECT_EVOLUTION.md for why lighter rerankers were rejected

### Cold Start Warning

On free/starter plans, services spin down after 15 minutes of inactivity. On restart, BGE-M3 and the reranker download from HuggingFace Hub (~1.6 GB total). First request after cold start may take 5–10 minutes.

**Mitigation:** Add `warm_up()` calls at application startup (already implemented in `app/main.py` lifespan handler).

## GitHub Actions CI/CD

### CI (`.github/workflows/ci.yml`)

Runs on every push/PR:
1. Python 3.11 setup
2. `pip install -r requirements.txt`
3. `pytest tests/ --ignore=tests/test_integration.py`
4. Next.js type check + lint + build

### CD (`.github/workflows/deploy.yml`)

Triggers on push to `main` after CI passes.

Requires these GitHub Actions secrets:
- `RENDER_BACKEND_DEPLOY_HOOK` — from Render dashboard → digitlaw-backend → Deploy hook
- `RENDER_FRONTEND_DEPLOY_HOOK` — from Render dashboard → digitlaw-frontend → Deploy hook

To get deploy hooks:
1. Render dashboard → select service
2. Settings → Deploy Hook → Copy URL
3. GitHub repo → Settings → Secrets and variables → Actions → New secret

## Qdrant Cloud Setup

### Initial setup

1. Create account at [cloud.qdrant.io](https://cloud.qdrant.io)
2. Create a cluster (free tier is sufficient for the corpus size)
3. Note the cluster URL: `https://YOUR-CLUSTER-ID.eu-west-2-0.aws.cloud.qdrant.io`
4. Create an API key (JWT format)

### Collection configuration

The ingestion script creates the collection automatically with:
- Vector size: 1024 (BGE-M3 dense)
- Distance metric: Cosine
- Sparse vector (BM25): enabled
- Payload fields: `law_type`, `law_name`, `law_number`, `law_year`, `article_number`, `category`

The collection name is `egypt_legal_rag` by default.

### Corpus ingestion

See the [README corpus ingestion section](../README.md#corpus-ingestion) or open `bayyinah_ingest.ipynb` for the GPU-accelerated Colab workflow.

## Environment Variables Reference

Full reference for all supported environment variables:

```env
# --- Required ---
GROQ_API_KEY=your_groq_key
QDRANT_URL=https://your-cluster.cloud.qdrant.io
# QDRANT_API_KEY required for Qdrant Cloud, leave empty for local Qdrant
QDRANT_API_KEY=your_jwt_token

# --- Application ---
APP_NAME=BAYYINAH
ENVIRONMENT=development          # development | production
DEBUG=false
LOG_LEVEL=INFO                   # DEBUG | INFO | WARNING | ERROR
LOG_JSON=true                    # Structured JSON logging (production)

# --- CORS ---
CORS_ORIGINS=["http://localhost:3000"]   # JSON array of allowed origins

# --- Qdrant ---
QDRANT_COLLECTION=egypt_legal_rag

# --- Embeddings ---
EMBEDDING_MODEL=BAAI/bge-m3
EMBEDDING_DEVICE=cpu             # cpu | cuda
EMBEDDING_DIM=1024

# --- Generation ---
GROQ_MODEL=openai/gpt-oss-120b
GROQ_TEMPERATURE=0.1
GROQ_MAX_TOKENS=2048

# --- Retrieval ---
RETRIEVAL_TOP_K=8                # Candidates passed to reranker
RETRIEVAL_SCORE_THRESHOLD=0.30   # Min cosine similarity to include a candidate
RERANK_TOP_N=5                   # Reranker output size

# --- Confidence scoring ---
CONFIDENCE_FALLBACK_THRESHOLD=0.35   # Below this → web search or fallback

# --- Guardrails ---
HALLUCINATION_MIN_OVERLAP=0.10   # Min token overlap between answer and citations
MAX_QUESTION_LENGTH=1000

# --- Query expansion (HyDE) ---
QUERY_EXPANSION_ENABLED=true
QUERY_EXPANSION_TIMEOUT_S=3.0

# --- Memory ---
REDIS_URL=redis://localhost:6379/0
MEMORY_MAX_TURNS=5
MEMORY_TTL_SECONDS=86400         # 24 hours

# --- Web search fallback ---
WEB_SEARCH_ENABLED=false         # Requires TAVILY_API_KEY
TAVILY_API_KEY=your_tavily_key

# --- Auth ---
SECRET_KEY=change-me-in-production

# --- Storage ---
UPLOAD_DIR=/data/uploads
MAX_FILE_SIZE_MB=15

# --- Frontend ---
NEXT_PUBLIC_API_URL=http://localhost:8000
```

## Troubleshooting

### "Connection refused" on startup
- Ensure Qdrant is running (Docker: `docker compose up qdrant`)
- Backend logs show `qdrant_connection_failed` — check `QDRANT_URL` and `QDRANT_API_KEY`

### 429 errors from Groq
- Check your Groq plan limits at console.groq.com
- Verify `GROQ_MODEL` is set correctly — some models have daily token limits

### OOM on Render
- Upgrade to pro plan (2 GB RAM)
- Or mount a disk and pre-download models in Dockerfile

### Empty retrieval / all fallback responses
- Corpus not ingested — run `scripts/ingest.py` or `bayyinah_ingest.ipynb`
- Wrong `QDRANT_COLLECTION` name — must match exactly: `egypt_legal_rag`
- Check `RETRIEVAL_SCORE_THRESHOLD` — if set too high (e.g., 0.45+), Arabic BGE-M3 scores may not reach it

### Frontend CORS errors
- Set `CORS_ORIGINS` in backend to include the exact frontend URL
- In production: `CORS_ORIGINS=["https://your-frontend.onrender.com"]`
